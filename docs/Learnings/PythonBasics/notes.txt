00. SETUP — HOW PYTHON RUNS
================================================================================

Python is an interpreted language. You write .py files; the interpreter runs them.

  python --version          # need 3.11+
  python -c "print('hi')"   # one-liner
  python hello.py           # run a file

REPL (interactive):
  python
  >>> 1 + 1
  2

.pyc / __pycache__:
  Python caches bytecode. Safe to ignore; don't commit it (.gitignore).

CloudOps note:
  Every service (auth-service, workers) is "Python process runs my package".


INTERVIEW
Q: Interpreted vs compiled?
A: Python compiles to bytecode then interprets on a VM (CPython). You usually
   don't ship a binary; you ship source + deps (or a container image).


================================================================================
01. VARIABLES & MEMORY MENTAL MODEL
================================================================================

A variable is a NAME bound to an OBJECT.

  service = "auth-service"
  port = 8000

Think:

  name "service" ──────► object "auth-service" (str)
  name "port"    ──────► object 8000 (int)

Rebinding:
  port = 8001          # name now points to a different object

Multiple names, same object:
  a = [1, 2]
  b = a
  b.append(3)
  # a is also [1, 2, 3]  — same list object

Identity vs equality:
  a == b     # same value?
  a is b     # same object in memory?
  x is None  # correct None check

CloudOps note:
  Request payload dicts are objects. Mutating them in a helper mutates the
  caller's data unless you copy.


INTERVIEW
Q: == vs is?
A: == value equality; is identity. Always `is None` / `is not None`.

02. NUMBERS, BOOLS, NONE
================================================================================

INT
---
  replicas = 3
  big = 10_000_000      # underscores OK for readability

FLOAT
-----
  cpu = 0.5
  # floats are approximate; for money use Decimal (rare in early CloudOps)

BOOL
----
  healthy = True
  ready = False
  # True/False are capitalized

NONE
----
  token = None          # "no value yet"

Conversions:
  int("42") -> 42
  str(42) -> "42"
  float("3.14") -> 3.14
  bool(0) -> False
  bool(1) -> True
  bool("") -> False
  bool("x") -> True

Truthiness (falsy values):
  False, None, 0, 0.0, "", [], {}, set(), ()

EXAMPLE — parse env with defaults:

  import os
  port = int(os.getenv("PORT", "8000"))
  debug = os.getenv("DEBUG", "false").lower() == "true"


INTERVIEW
Q: Why is bool a subclass of int?
A: Historically True==1, False==0. Don't rely on that in APIs; use real bools.

03. STRINGS (str)
================================================================================

  email = "admin@cloudops.local"
  role = 'admin'                 # single or double quotes
  multi = """line1
  line2"""

F-STRINGS (use these always):
  name = "auth-service"
  msg = f"starting {name} on {8000}"

Useful methods:
  s.lower(), s.upper(), s.strip()
  s.startswith("/api/")
  s.endswith(".json")
  s.replace("old", "new")
  s.split(",")                   # str -> list
  ",".join(["a", "b"])           # list -> str
  s.find("x"), s.index("x")
  len(s)

Indexing / slicing:
  s = "cloudops"
  s[0]      # 'c'
  s[-1]     # 's'
  s[0:5]    # 'cloud'
  s[::-1]   # reverse

Immutability:
  s[0] = "C"   # TypeError — strings cannot be changed in place
  s = "C" + s[1:]

Formatting for logs/errors:
  raise ValueError(f"unknown role: {role!r}")

RAW / PATHS:
  Prefer pathlib over raw Windows path strings.


EXAMPLES FOR CLOUDOPS

  path = "/api/v1/users/42"

      ...

  header = "Bearer eyJabc.def"
  scheme, _, token = header.partition(" ")
  # scheme == "Bearer", token == "eyJabc.def"


INTERVIEW
Q: Are strings mutable?
A: No. Any "change" creates a new string object.

Q: f-string vs format vs %?
A: Prefer f-strings in modern Python (3.6+). Clear and fast.

04. LISTS
================================================================================

Ordered, mutable sequence.

  services = ["auth", "deploy", "ai"]
  services.append("worker")
  services.extend(["metrics", "logs"])
  services.insert(0, "gateway")
  services.pop()                 # remove last
  services.remove("ai")          # remove by value
  services[0] = "auth-service"   # mutate
  len(services)
  "auth" in services

Slicing:
  services[1:3]
  services[:]                    # shallow copy

Sort:
  nums = [3, 1, 2]
  nums.sort()                    # in place
  sorted(nums)                   # new list

Nested (like simplified manifests):
  pods = [
      {"name": "api-1", "ready": True},
      {"name": "api-2", "ready": False},
  ]
  ready_names = [p["name"] for p in pods if p["ready"]]


Copy pitfall:
  a = [1, 2]
  b = a          # same object
  c = a.copy()   # shallow copy
  d = list(a)    # shallow copy
  import copy
  e = copy.deepcopy(a)


INTERVIEW
Q: list.append vs list.extend?
A: append adds one element; extend adds each element from an iterable.

Q: How to copy a list?
A: a.copy(), list(a), or a[:] — shallow. Nested structures need deepcopy.

05. TUPLES
================================================================================

Ordered, immutable sequence.

  point = (10, 20)
  single = (10,)          # comma required for 1-element tuple
  x, y = point            # unpacking

Why use tuples?
  - Fixed records: (status_code, body)
  - Dict keys (if contents hashable)
  - Return multiple values: return token, expires_at

  def divide(a: int, b: int) -> tuple[int, int]:
      return a // b, a % b

  q, r = divide(10, 3)


INTERVIEW
Q: Tuple vs list?
A: Tuple immutable + often means "fixed structure"; list means "collection that grows".

06. DICTS (most important collection for APIs)
================================================================================

Key → value map. JSON objects become dicts.

  user = {
      "email": "a@b.com",
      "role": "admin",
      "active": True,
  }

Access:
  user["email"]
  user.get("phone")              # None if missing
  user.get("phone", "n/a")       # default
  user["role"] = "viewer"
  del user["active"]
  "email" in user                # key membership

Iterate:
  for key in user:
      ...
  for key, value in user.items():
      ...
  user.keys(); user.values()

Merge (3.9+):
  a = {"x": 1}
  b = {"y": 2}
  c = a | b

Nested dict (K8s-like):
  manifest = {
      "metadata": {
          "name": "web",
          "labels": {"app": "web", "env": "prod"},
      },
      "spec": {"replicas": 2},
  }
  replicas = manifest["spec"]["replicas"]
  app = manifest["metadata"]["labels"]["app"]

Safe nested get pattern:
  labels = manifest.get("metadata", {}).get("labels", {})


EXAMPLE — normalize API payload

  def normalize_deploy(payload: dict) -> dict:
      return {
          "name": payload["name"],
          "image": payload.get("image", "nginx:latest"),
          "replicas": int(payload.get("replicas", 1)),
      }


INTERVIEW
Q: What can be a dict key?
A: Hashable types: str, int, tuple of hashables — not list/dict/set.

Q: dict.get vs []?
A: [] raises KeyError if missing; get returns None/default.

Q: Why dicts for JSON APIs?
A: JSON object ↔ Python dict is the natural mapping FastAPI/Pydantic use.

07. SETS
================================================================================

Unordered unique elements. Fast membership tests.

  roles = {"admin", "viewer", "operator"}
  roles.add("auditor")
  "admin" in roles               # O(1) average

Operations:
  a | b        # union
  a & b        # intersection
  a - b        # difference

CloudOps use:
  required = {"deploy:write", "pods:read"}
  granted = {"pods:read", "logs:read"}
  missing = required - granted   # {"deploy:write"}


INTERVIEW
Q: When set over list?
A: Uniqueness + fast `in` checks (permissions, tags, namespaces).

  // floor division
  %  remainder

09. CONTROL FLOW
================================================================================

IF / ELIF / ELSE
----------------
  if status == 200:
      ...
  elif status in (401, 403):
      ...
  else:
      ...

FOR
---
  for svc in services:
      print(svc)

  for i, svc in enumerate(services, start=1):
      print(i, svc)

  for key, value in user.items():
      ...

WHILE
-----
  retries = 3
  while retries > 0:
      ok = try_connect()
      if ok:
          break
      retries -= 1
  else:
      # while-else: runs if loop did NOT break
      raise RuntimeError("db unreachable")

MATCH / CASE (3.10+) — great for status/commands
------------------------------------------------
  match status:
      case 200 | 201:
          ...
      case 401 | 403:
          ...
      case 404:
          ...
      case _:
          ...

  match event:
      case {"type": "deploy", "name": name}:
          ...
      case {"type": "scale", "replicas": int(r)} if r > 0:
          ...
      case _:
          ...

break / continue / pass
  break     — leave loop
  continue  — next iteration
  pass      — empty placeholder


EXAMPLE — RBAC gate

  def assert_can_deploy(role: str) -> None:
      if role not in {"admin", "operator"}:
          raise PermissionError("deploy not allowed")


INTERVIEW
Q: for-else / while-else?
A: else runs if loop finished without break — useful for "not found" patterns.

10. FUNCTIONS (DEEP) — WI-009 / WI-224
================================================================================

Definition:
  def health() -> dict[str, str]:
      return {"status": "ok"}

Parameters:
  def deploy(name: str, image: str, replicas: int = 1) -> dict:
      return {"name": name, "image": image, "replicas": replicas}

Positional vs keyword calls:
  deploy("web", "nginx:1.27")
  deploy(name="web", image="nginx:1.27", replicas=2)

*args — extra positionals as tuple:
  def log_lines(*lines: str) -> None:
      for line in lines:
          print(line)

**kwargs — extra keywords as dict:
  def build_headers(**kwargs: str) -> dict[str, str]:
      return kwargs

Keyword-only (after *):
  def create_user(email: str, *, role: str = "viewer") -> None:
      ...

Positional-only (before /) — advanced, know it exists:
  def f(a, b, /, c):
      ...

Return multiple values = return a tuple:
  return access_token, refresh_token

Docstrings:
  def hash_password(password: str) -> str:
      """Return a secure password hash for storage."""
      ...

Mutable default pitfall (CLASSIC INTERVIEW):
  # BAD
  def add_item(item, bucket=[]):
      bucket.append(item)
      return bucket

  # GOOD
  def add_item(item, bucket=None):
      if bucket is None:
          bucket = []
      bucket.append(item)
      return bucket

Early return style (clean APIs):
  def get_role(user: dict | None) -> str:
      if user is None:
          return "anonymous"
      return user.get("role", "viewer")

Functions are first-class:
  def apply(fn, value):
      return fn(value)
  apply(str.upper, "ok")


CloudOps mapping:
  FastAPI endpoint = normal Python function
  Depends(...) injects arguments
  return dict/Pydantic → JSON response


INTERVIEW
Q: *args vs **kwargs?
A: *args tuple of extra positional; **kwargs dict of extra keyword args.

Q: Why avoid mutable defaults?
A: Default object is created once; later calls share/mutate the same list/dict.

Q: What does returning nothing return?
A: None.

11. SCOPE — LEGB
================================================================================

Python looks up names in order:
  L — Local
  E — Enclosing (nested functions)
  G — Global (module)
  B — Builtins (len, str, ...)

  x = "global"

  def outer():
      x = "enclosing"
      def inner():
          print(x)     # enclosing
      inner()

global / nonlocal (use rarely):
  Prefer passing values and returning results over mutating globals.
  Config should come from env/settings objects, not scattered globals.


INTERVIEW
Q: What is LEGB?
A: Name resolution order: Local, Enclosing, Global, Builtins.

12. COMPREHENSIONS & GENERATOR EXPRESSIONS — WI-223
================================================================================

List comprehension:
  names = [s.upper() for s in services]
  active = [p for p in pods if p["ready"]]

Dict comprehension:
  role_map = {u["email"]: u["role"] for u in users}

Set comprehension:
  namespaces = {p["ns"] for p in pods}

Generator expression (lazy):
  total = sum(x * x for x in range(10))

When NOT to use comprehensions:
  Complex multi-step logic — use a normal for-loop for readability.


INTERVIEW
Q: List comp vs generator expr?
A: [...] builds full list in memory; (...) yields lazily — better for large data.

13. TYPE HINTS — PROJECT CRITICAL
================================================================================

Hints document intent; FastAPI/Pydantic use them for validation & OpenAPI.

  def get_user(user_id: int) -> dict[str, str] | None:
      ...

Common forms (3.10+):
  str | None
  list[str]
  dict[str, int]
  tuple[str, int]
  set[str]

Older typing module (still seen):
  from typing import Optional, List, Dict, Any, Callable, Iterable
  Optional[str] == str | None

Any — escape hatch (avoid when possible)
Callable[[int, str], bool]
Iterable[str]

Type aliases:
  JSONDict = dict[str, object]
  Headers = dict[str, str]

TypedDict (structured dict):
  from typing import TypedDict
  class DeployPayload(TypedDict):
      name: str
      image: str
      replicas: int


EXAMPLE — CloudOps flavored

  from enum import Enum

  class Role(str, Enum):
      ADMIN = "admin"
      VIEWER = "viewer"
      OPERATOR = "operator"

  def can_delete_cluster(role: Role) -> bool:
      return role is Role.ADMIN


INTERVIEW
Q: Do type hints enforce types at runtime?
A: Not by themselves. Pydantic/FastAPI enforce at API boundaries; mypy/pyright
   check statically.

Q: Why hints in FastAPI?
A: Request parsing, validation errors (422), and auto OpenAPI docs.

16. EXCEPTIONS — WI-226
================================================================================

  try:
      user = find_user(email)
  except UserNotFoundError as exc:
      ...
  except Exception:
      logger.exception("unexpected")
      raise
  finally:
      db.close()

Raise:
  raise ValueError("replicas must be >= 1")

Custom hierarchy (recommended for APIs):

  class DomainError(Exception):
      def __init__(self, message: str, code: str = "domain_error"):
          self.message = message
          self.code = code
          super().__init__(message)

  class NotFoundError(DomainError):
      def __init__(self, message: str = "Not found"):
          super().__init__(message, "not_found")

  class AuthError(DomainError):
      def __init__(self, message: str = "Unauthorized"):
          super().__init__(message, "unauthorized")

  class ForbiddenError(DomainError):
      def __init__(self, message: str = "Forbidden"):
          super().__init__(message, "forbidden")

Map later in FastAPI:
  NotFoundError → 404
  AuthError → 401
  ForbiddenError → 403
  Validation → 422
  unknown → 500

Rules:
  - Catch what you can handle/translate
  - Don't swallow exceptions silently
  - Don't use bare `except:`


INTERVIEW
Q: try/except/finally roles?
A: except handles; finally cleans up always.

Q: Why custom exceptions?
A: Stable domain errors → consistent HTTP responses.

17. CLASSES & OOP — WI-225 foundation
================================================================================

  class User:
      def __init__(self, email: str, role: str) -> None:
          self.email = email
          self.role = role

      def is_admin(self) -> bool:
          return self.role == "admin"

      def __repr__(self) -> str:
          return f"User(email={self.email!r}, role={self.role!r})"

  u = User("a@b.com", "admin")

Class attributes vs instance attributes:
  class Config:
      DEFAULT_REPLICAS = 1          # shared class attr
      def __init__(self, name: str):
          self.name = name          # per-instance

Inheritance:
  class AppError(Exception):
      ...
  class NotFoundError(AppError):
      ...

Composition over inheritance for services:
  class AuthService:
      def __init__(self, repo, hasher):
          self._repo = repo
          self._hasher = hasher

      def login(self, email: str, password: str) -> str:
          user = self._repo.get_by_email(email)
          ...

@classmethod / @staticmethod (know the difference):
  @classmethod — receives class; alt constructors
  @staticmethod — no self/cls; namespaced function

@property — computed attribute style


INTERVIEW
Q: Class vs object?
A: Class = blueprint; object = instance.

Q: Inheritance vs composition?
A: is-a vs has-a. Prefer composition for business services.

Q: What is self?
A: The instance the method is bound to.

19. DECORATORS
================================================================================

A decorator wraps a function to add behavior.

  import functools
  import time

  def timed(fn):
      @functools.wraps(fn)
      def wrapper(*args, **kwargs):
          start = time.perf_counter()
          try:
              return fn(*args, **kwargs)
          finally:
              elapsed = time.perf_counter() - start
              print(f"{fn.__name__} took {elapsed:.4f}s")
      return wrapper

  @timed
  def work():
      ...

Stacking:
  @decorator_a
  @decorator_b
  def f():
      ...
  # equivalent to f = decorator_a(decorator_b(f))

CloudOps:
  @app.get("/health")          # FastAPI registers route
  @router.post("/login")
  Depends is related DI pattern


INTERVIEW
Q: What is a decorator?
A: A callable that takes a function and returns a new callable, used with @syntax.

Q: Why functools.wraps?
A: Preserves original function name/doc for debugging and OpenAPI-ish metadata.

21. ITERATORS & GENERATORS (yield)
================================================================================

Iterable = can be looped (list, dict keys, files...)
Iterator = object with __next__ producing values

Generator function:
  def countdown(n: int):
      while n > 0:
          yield n
          n -= 1

  for x in countdown(3):
      print(x)

FastAPI dependency pattern:
  def get_db():
      db = SessionLocal()
      try:
          yield db          # pause here while endpoint runs
      finally:
          db.close()


INTERVIEW
Q: What does yield do?
A: Returns a value and pauses function state; makes a generator.

Q: Why yield in get_db?
A: Setup before request, teardown after — like a context manager for DI.

24. ASYNC BASICS — WI-228
================================================================================

  import asyncio
  import httpx

  async def fetch(url: str) -> int:
      async with httpx.AsyncClient() as client:
          r = await client.get(url)
          return r.status_code

  async def main():
      code = await fetch("https://httpbin.org/get")
      print(code)

  asyncio.run(main())

Mental model:
  await parks this coroutine until I/O completes; event loop runs other work.

Rules of thumb:
  - async helps concurrent I/O (HTTP, DB drivers)
  - does not magically speed CPU-bound crypto/parsing
  - don't call blocking time.sleep / heavy sync I/O inside async without care


INTERVIEW

A: Coroutine function vs normal function. FastAPI supports both; async shines for I/O.

26. IDIOMS & PITFALLS (interview traps)
================================================================================

1) Mutable default args — NEVER
2) `is` for None only (not for ints/strings intern tricks)
3) Shallow vs deep copy on nested manifests
4) Catching Exception too broadly
5) Modifying list while iterating — iterate copy or build new list
6) Using bare except
7) Shadowing builtins: don't name variables list, dict, id, type carelessly
8) Comparing floats with == for critical equality
9) Assuming dict order — modern Python preserves insertion order, but design
   APIs without relying on order unless specified
10) Encoding: always UTF-8 for files/APIs
